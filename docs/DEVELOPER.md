# 開発メモ：面に沿ってスライド（プロポーショナル） 2.1.0

使う人向けの説明は [manual.html](manual.html)。ここは直す人向け（仕組み・テスト・実測・決めたことの理由）。

## ファイルの分担

| ファイル | 中身 |
|---|---|
| `core.py` | 計算だけ。`SlideContext`（開始時の形・面・島・視点）→ `compute_weights`（範囲の重み）→ `solve`（新しい位置）→ `apply_positions` |
| `__init__.py` | モーダルのオペレーター `mesh.surface_slide_proportional`、新しいキー `mesh.surface_slide_new_key`、マニュアルを開く `mesh.surface_slide_help`、N パネル、描画、キーマップ（Mesh・Shift+Alt+V） |
| `ui_text.py` | 画面の文言。`header_text`・`status_items`・`MSG`・`MODAL_KEYS`（マニュアルのキー表の正本） |

## 仕組み

### 重み（範囲）
- 種＝選んだ頂点（左右対称なら鏡の相手も）。種からの距離を Blender と同じ減衰曲線（`core.falloff`）に通す
- 距離は「つながった面だけ」ON なら辺をたどった Dijkstra、OFF なら KD ツリーのまっすぐの距離。どちらもワールド空間
- どの種から届いたか（`src`）を覚えておく。口を開くときの上唇・下唇の向きや、口の中の頂点が唇についていくのに使う

### 面に沿った移動（`slide`）
- 沿わせる面＝「選んだ頂点と同じ島」かつ「隠していない」かつ「視点を向いている（法線・視線 < 0.25）」面だけで BVH を作る。口の中・裏面・別パーツに吸い付かないため
- 移動量 × 重みを、辺の平均の半分の歩幅（最大 64 歩）に分けて進み、1 歩ごとにいちばん近い面の点へ乗せる
- いちばん近い面の向きが今の向きと逆（内積 < 0.3）なら、近くで向きの合う面を探して乗せる
- 沿わせる面が無い頂点（口の中など）は、自分の種が実際に動いた量 × 重みの比でついていく
- 「沿わせる面：ベースの形」では、Basis の面の上で歩いた差分を、いまの形に足す

### 回転（`R`、2.1.0）
- 中心＝選択の真ん中（左右対称なら元の側の選択だけの真ん中：`rotation_center`）。軸＝X/Y/Z を決めていれば その軸、決めていなければ「面の向き」（選択に触れる面の法線の和を、画面の手前側にそろえたもの：`selection_normal_world`）か、`rot_view` なら画面の手前向き
- 重みは**角度にかける**（`angle × w`）。回った位置との直線で混ぜる（Blender の R のやり方）と、角度が大きいとき中心側へ縮むため
- 面に沿わせるときは、角度を 5° 以下・歩幅（辺の平均の半分）以下に刻み、1 歩ごとに「いまの位置を中心のまわりに回す → 面へ乗せる」（`slide_rotate`）。弧の上を歩くので 120° でも半径が保たれる（平面で差 3.5e-07）
- マウス：中心（画面上）からの角度の差を積み上げる（±180° をまたいでも続く）。軸が奥を向いているときは符号を反転して、見た目の回る向きとマウスの向きをそろえる
- 左右対称では反対側に `(-dx, dy, dz)` を写すので、自然に逆向きの回転になる
- 軸が面に寝ている（`|軸・面の向き| < 0.3`）ときはヘッダーに ⚠（面に沿うと回れない）

### 口を開く（`A`）
- 選んだ頂点ごとに、視点を向いた隣の面の中心が画面の上下どちらにあるかで、上唇（-1）・下唇（+1）・口角（0）に分ける（`classify_open`、しきい値 0.25）
- 口角は動かさず、範囲の距離の通り道にもしない（上唇と下唇が口角を回って混ざらないように）
- 下唇は移動量どおり、上唇は `-上唇の割合 ×` 移動量。動きは画面の上下だけ（軸を決めていないとき。口を開く中に軸を決めたときや、F9 で移動量を打ったときは、その向きに動く）
- まるく開く：口の幅の方向に放物線 `1-u²` の強さ（真ん中 1・口角 0）

### 左右対称（`M`）
- 相手は Basis（無ければ開始時の形）で `(-x, y, z)` の位置にある頂点（許し 1% × 辺の平均）
- 選択の X の平均で「元の側」を決め、元の側を解いてから、反対側に `(-dx, dy, dz)` を写す。中心線の頂点は X を動かさない

### 半径の自動調整（`suggest_radius`）
- 目安＝max(6 × 選択まわりの辺の平均, 0.5 × 選択の広がり)
- 今の半径が目安の 10 倍より大きい・辺の平均より小さいなら目安に直してお知らせ。ただし、この道具で最後に確定した半径か、N パネルの「はじめの設定」で決めた半径（どちらも `Scene.surface_slide.last_radius` に入る）と同じならそのまま

## 2.0.0 で使いやすさのために変えたこと（1.x から）

レビューで「使いづらい」の原因として挙がったものと、その直し。

| 前 | 後 |
|---|---|
| 右クリックメニューから選ぶと、量 0 で実行して終わる | `INVOKE_REGION_WIN` で呼び、十字カーソルで始める位置をクリック（`DEPENDS_ON_CURSOR`） |
| 半径がシーンの値のまま（factory 1 m・前のモデルの 0.5 mm） | 顔の大きさに合わせて直してお知らせ（上の自動調整） |
| ホイールの向き・C/O の意味が Blender と逆 | Blender の G と同じ（ホイール下＝広く、C＝軸を解除、Shift+O＝減衰、Alt+O＝接続のみ）。独自は F・B・M・A。R（回転）・Ctrl のスナップ・中ボタンの軸決めは無い |
| S で中心の近くから始めると暴れる | 距離の増分で倍率を決める：`1 + (離した距離 − 始めの距離) / max(始めの距離, 80px × UI 倍率)`（中心の上から始めて 30px 離すと 1.2〜1.5 倍。ui_smoke で確かめている） |
| 書き込み先・量が見えない | ヘッダーに量・範囲・書き込み先・影響数・⚠、ステータスバーにキーと ON/OFF |
| Basis・ロック中のキーにも黙って書く | 止めて理由と直し方を出す |
| 左右対称が無い | `M`（メッシュの X ミラーで初期化） |
| 閉じた口を開けられない（S→Z では唇が口の中へ入る） | `A`（口を開く） |
| 使い方がどこにも無い | `docs/manual.html`、N パネルの「使い方を開く」 |
| 回転が無い | 2.1.0 で `R` を追加（上の「回転」） |
| 「新しいキーを作って始める」でやめると空のキーが残る | やめたら作ったキーを消す（Basis も作っていたら Basis ごと） |

## 実測（市販アバターの顔メッシュ・2026-10-23）

| 操作 | 結果 |
|---|---|
| 下唇だけを移動で 8 mm 下げる（範囲 2 cm） | 真ん中が 6.30 mm 下がる（面に沿うぶん減る）、裏返った面 4 |
| 口を開く 8 mm（まるく・四角・左右対称） | 真ん中のすき間 +7.98 mm、裏返った面 2、動いた頂点 280 |
| 参考：そのアバターに付属の「あ」のキー | 真ん中のすき間 +8.97 mm |
| 左右対称 | 鏡の相手どうしの動きの差 < 1e-6 |

まるく開くの形の比較（8 mm 開いたときの裏返った面）：楕円 `sqrt(1-u²)` 8 枚・口角にしわ、放物線 `1-u²` 2 枚・丸い「あ」、`cos` 0 枚だが V 字にとがる → 放物線にした。

## 知っている弱いところ

- F9 のパネルは、画面の下のほうで開くと最後の行（左右対称）が切れて薄く見えることがある（Blender のポップアップの高さ制限）
- 操作中のヘッダーは 1 行なので、ウィンドウが狭いと後ろの項目（⚠ など）が見えない。ステータスバーにも同じ ON/OFF を出している
- メニューから選んだときの十字カーソルの間、Blender 本体の「Input pending」が英語で出る（アドオンからは変えられない）
- シェイプキーの値を途中（0.5 など）にすると、曲がった面の上を大きく動かした頂点は面の内側を通る（シェイプキーが直線の補間のため）
